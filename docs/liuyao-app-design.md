## 1. 结论先行

六爻应作为 Passport OS 的独立离线排盘应用，而不要塞进现有八字页。两者的共同点是传统历法与五行语义，但读取任务不同：

- 八字先读固定四柱，再横向看大运、纵向看流年。
- 六爻先读六条爻线，同时核对六神、六亲、纳甲、世应、伏神与动变。

当前实现采用四屏状态：

1. 起卦方式：竖屏页面，提供时间起卦与手动摇卦。
2. 手动摇卦：竖屏三枚钱币逐爻摇六次，钱面与爻值留痕可核对。
3. 六爻主盘：确认后切到横屏，本卦、变卦、月日旬空与六行完整盘面同屏。
4. 卦意：横屏并列显示本卦、变卦的白话解释；无动爻时只解释本卦。

时间起卦不进入额外编辑页；数字起卦已移除。

界面的专业感来自身份明确的盘面语法，而不是增加装饰：

- 阳爻是一条连续横线，阴爻是一分为二的横线。
- 阴爻变阳爻标 `X →`，阳爻变阴爻标 `O →`，不改变原爻线本身。
- 世、应直接写在行内，既不留空白列，也不另开“世应页”。
- 六亲纳甲使用五行色，但关系文字始终存在，不能只靠颜色辨别。
- 本卦与变卦并排，靠“之”和左右对齐建立关系。
- 设备只整理可核对关系，不自动输出“吉”“凶”或无法追溯的解释。

## 3. 产品定位与边界

### 3.1 定位

六爻排盘是一个“传统规则可核对”的离线工具：

- 按时间或手动摇卦方式生成六爻，并显示取数、钱面与动爻过程。
- 完整显示本卦、变卦、动爻、八宫、世应、纳甲、六亲、六神、伏神、旬空和月日关系。
- 当前版本只展示完整盘面和双卦白话，不提供用神选择页或单爻详情页。

它不承担以下职责：

- 自动判断婚姻、疾病、投资、诉讼或健康的最终结果。
- 用生成式 AI 替用户决定用神或吉凶。
- 在缺少规则来源时隐藏中间信息，只给一句结论。
- 未经用户同意上传问事、起局时间或历史盘面。

## 4. 用户流程

### 4.1 首次起卦

```text
启动器
  -> 六爻排盘
  -> 竖屏选择起卦方式
  -> 时间起卦直接生成横屏盘面
  -> 或手动摇卦逐爻摇满六次后生成横屏盘面
  -> 确定查看本卦与变卦的白话解释
```

### 4.2 时间起卦

```text
起卦方式
  -> 时间起卦
  -> 读取设备当前时间
  -> 立即生成横屏盘面
```

### 4.3 手动摇卦

```text
起卦方式
  -> 手动摇卦
  -> 读取设备当前时间，进入竖屏摇卦页
  -> 每次确定摇一爻，三枚钱币落定后记录背/字与 6/7/8/9
  -> 由初爻向上摇满六爻
  -> 确定生成横屏盘面
```

摇卦时间在进入摇卦页时固定，六爻共用同一日辰、月建、旬空和六神。

### 4.4 修改后重起

```text
六爻主盘
  -> 长按确定（整机返回手势）
  -> 手动摇卦返回已完成摇卦页；时间起卦返回起卦方式页
  -> 再次长按确定：手动摇卦有爻时重摇，空盘时回到起卦方式
```

### 4.5 从用神回到原爻（后续）

```text
取用参断
  -> 上下切换用神候选
  -> 确定
  -> 定位到该六亲重新出现的爻行
  -> 定位并高亮该六亲所在爻
```

如果一个六亲在多爻出现，确定后显示“第几爻至第几爻”的可选列表，不静默选择第一条。

## 5. 信息架构

### 5.1 起卦方式

首屏保持竖屏，顶栏左侧直接显示“六爻排盘-起卦方式”，正文只包含两种起卦方式：

1. 时间起卦。
2. 手动摇卦。

当前版本不选择事项类别，也不输入问事正文。手动摇卦由确定键触发，不要求甩动设备（硬件无加速度计）。

### 5.2 时间起卦

时间起卦不再进入日期时间编辑器。用户在竖屏首屏选中“时间起卦”并确定后：

- 读取设备当前本地时间。
- 转换为农历年月日、年支和时支。
- 计算上卦、下卦和动爻。
- 保持起卦页竖屏，在结果生成后切换到 320×240 横屏盘面。

这种流程避免重复选择时间；需要补录其他时间的能力留到后续版本。

### 5.3 手动摇卦

竖屏摇卦页固定显示：

1. 顶栏“六爻排盘-手动摇卦”。
2. 强调色章节条“手动摇卦”，右侧显示“第 N / 6 爻”。
3. 三枚钱币托盘：每枚显示“背”或“字”，托盘下方显示本爻三枚钱面的组合与爻值。
4. 六爻堆栈：上爻在上、初爻在下，每行保留本爻的三枚钱面、爻线、6/7/8/9 与 `X →`/`O →`。
5. 底部按键提示。

摇动效果：确定键触发后，三枚钱币在托盘内左右错位抖动、钱面每 60ms 交替背/字，约 720ms 落定；设计稿另含 200ms 钱币归位与 180ms 爻线落入，当前实现落定后立即刷新，作为后续动效优化。动画只使用位置变化和文本切换，不引入图片、帧缓冲或常驻循环；确定可跳过，连续按键不叠加。

六爻全部落定前不生成盘面。六爻完成后状态行显示本卦与变卦名，确定进入横屏主盘。长按确定是整机返回手势：有爻时清空重摇；空盘时回到起卦方式。

### 5.4 六爻主盘

主盘从第 6 爻到第 1 爻自上而下排列，所有行共享五列：

| 列 | 内容 | 读法 |
| --- | --- | --- |
| 六神 | 青龙、朱雀、勾陈、螣蛇、白虎、玄武 | 从初爻向上按日干顺排 |
| 六亲纳甲 | 例如“妻财乙卯” | 六亲与纳甲绑定，五行只给文字着色 |
| 本卦 | 阳爻或阴爻 | 图形是主识别面 |
| 位 | 世、应、`X →`、`O →` | 阴变阳与阳变阴必须写清方向 |
| 变爻 | 例如“子孙甲子” | 静爻留空，只有变爻显示结果 |

顶部信息：

- 顶栏左侧合并显示“六爻排盘-时间起卦”或“六爻排盘-手动摇卦”。
- 月建、日辰、时支。
- 旬空，使用边框标签而不是把“空”染成危险色。
- 本卦名、之卦名。
- 宫、游魂/归魂、世应位置。

固定尺寸建议：

| 区域 | 位置与尺寸 |
| --- | --- |
| 顶栏 | y=0，h=26 |
| 日期、干支、旬空摘要 | x=8，y=28，w=304，h=60 |
| 双卦盘面 | x=8，y=89，w=304，h=127 |
| 本卦与变卦标题 | y=90，h=24 |
| 六爻行 | y=115，每行 h=16 |
| 底部分隔线 | x=8，y=218，w=304，h=1 |

行宽分配：

- 六神 24px。
- 六亲纳甲 54px。
- 爻线 40px。
- 世应/变向标记 30px。
- 变爻 68px。

这套分配允许六亲和纳甲保持在同一条基线，不需要把“六亲”和“地支”拆成上下两行。

### 5.5 卦意

主盘按确定进入横屏“卦意”页，本卦与变卦左右并列：

- 上方居中显示卦名。
- 下方显示一段简短白话说明，解释该卦的传统意象与行动提示。
- 两卦说明都留在同一屏，用户不需要逐爻翻页。
- 文字保持中性，不自动生成具体吉凶、金额、疾病或关系结论。

64 卦白话摘要内置在纯 C 表中，与卦名 ID 一一对应，离线可用。

### 5.6 取用参断（后续）

用途是把判断所需的核心关系集中到一屏：

- 用神及所在爻位。
- 原神、忌神、仇神。
- 月建、日辰对用神的状态。
- 用神是否空、破、冲、合、伏、动。
- 用神动化后与本爻的生克关系。
- 明确写出“结论保留给解读者”。

类别只产生建议。例如“事业求财”可优先建议妻财，但官鬼、父母也可能因具体问题成为用神，因此用户必须确认或改选。

## 7. 专业规则边界

以下规则必须由纯 C 核心实现，并配可重复的主机测试。UI 只能读取核心结果，不能自行临时推导。

### 7.1 起卦方式与取数

首版固定支持时间起卦和手动摇卦。两者都先输出“六爻阴阳数组 + 动爻位置（0–6 个）”，再进入同一套八宫、纳甲、六亲和世应计算。

#### 7.1.1 时间起卦

默认规则：

- 年数使用当年地支序数：子 1、丑 2、寅 3、卯 4、辰 5、巳 6、午 7、未 8、申 9、酉 10、戌 11、亥 12。
- 月数使用农历月数 1–12。
- 日数使用农历日数 1–30。
- 时数使用时辰地支序数，规则同年支。
- 上卦数 = `(年数 + 月数 + 日数) mod 8`，余 0 按 8。
- 下卦数 = `(年数 + 月数 + 日数 + 时数) mod 8`，余 0 按 8。
- 动爻数 = `(年数 + 月数 + 日数 + 时数) mod 6`，余 0 按 6。
- 卦数映射：1 乾、2 兑、3 离、4 震、5 巽、6 坎、7 艮、8 坤。

时间起卦只产生一个动爻。公历输入先经现有历法模块转换为农历年月日与干支；早子时/晚子时、标准时/真太阳时继续沿用全局设置。

#### 7.1.2 手动摇卦

每次摇卦使用三枚钱币，每枚独立产生背面或字面：

- 背面（无字）计 3，属阳；字面计 2，属阴。
- 三枚合计 6–9：
  - 6（三字）= 老阴，阴爻动，标 `X →`。
  - 7（一背两字）= 少阳，阳爻静。
  - 8（两背一字）= 少阴，阴爻静。
  - 9（三背）= 老阳，阳爻动，标 `O →`。
- 由初爻向上摇六次，每次一枚合计值对应一爻。
- 六爻互相独立，动爻数量为 0–6，不再限制为单动爻。
- 每爻落定后钱面与爻值在本页保留；进入盘面后不可修改，重摇会清空全部六爻。
- 随机数由设备随机源逐枚产生；同一爻落定后不再重抽。
- 摇卦时间在进入摇卦页时固定，六爻共用同一时间；时间未同步时不生成盘面。

#### 7.1.3 统一转成六爻

- 本卦每爻：6、8 为阴，7、9 为阳。
- 动爻：6 与 9；变卦在本卦基础上翻转全部动爻。
- 时间起卦仍只产生一个动爻；手动摇卦可产生多个动爻。
- 无动爻时 `X →` 与 `O →` 都不出现，也不制造变卦；主盘与卦意只呈现本卦。

### 7.2 八宫、世应

- 按京房八宫查找 64 卦所属宫、宫五行、本宫/一世至五世/游魂/归魂。
- 世位依次为六世、一世、二世、三世、四世、五世、游魂四世、归魂三世。
- 应位为世位对面三爻，循环 1 至 6。
- 不能按“八卦名相同”猜测世位，必须有 64 卦表。

### 7.3 纳甲与六亲

纳甲以八经卦内外两组的固定干支表生成。六亲以宫五行为“我”：

- 同我者兄弟。
- 我生者子孙。
- 生我者父母。
- 我克者妻财。
- 克我者官鬼。

干支五行不能从当前主题色反推，必须先由字符索引确定木火土金水，再调用主题色。

### 7.4 六神

按起卦日干确定初爻六神，再向上顺序排：

| 日干 | 初爻 |
| --- | --- |
| 甲乙 | 青龙 |
| 丙丁 | 朱雀 |
| 戊 | 勾陈 |
| 己 | 螣蛇 |
| 庚辛 | 白虎 |
| 壬癸 | 玄武 |

六神顺序为青龙、朱雀、勾陈、螣蛇、白虎、玄武。

### 7.5 日月、旬空与伏神

- 月建、日辰取起卦时刻的节气月与日干支。
- 当天的旬空由日柱所属旬计算。
- 月破取与月建相冲的地支。
- 日冲、六合、六冲、三合、入墓作为状态事实展示。
- 伏神只从本宫首卦中补当前卦缺失的六亲，并记录伏藏在第几爻。
- 不把伏神与当前爻的六亲混成一个标签。

### 7.6 用神与关系

- 用神由用户最终确认，类别只给建议。
- 生用神者为原神，克用神者为忌神，克原神者为仇神。
- 当六亲对应五行有多个出现爻，必须保留每个候选爻位。
- 动爻的变爻六亲仍按原宫五行计算。
- 所有自动整理只写生克、空破、冲合、伏动与化变关系，不写确定性事件结果。

## 8. 视觉设计

### 8.1 爻线语法

| 形态 | 含义 |
| --- | --- |
| 32×3px 连续横线 | 阳爻 |
| 两段 14×3px、中缝 4px | 阴爻 |
| `X →` | 阴爻变阳爻 |
| `O →` | 阳爻变阴爻 |
| 行内“世”“应” | 宫位归属 |
| 左右卦名与“之” | 本卦到变卦 |

爻线是应用最强的识别物，因此不把每一爻装进卡片，也不使用金色渐变、圆形八卦背景或装饰纹理。

### 8.1.1 摇卦页

- 三枚钱币为 48px 圆形，2px `UI_BORDER` 描边，`UI_SURFACE_ALT` 底色，钱面 20px 显示“背”或“字”。
- 待摇时钱币只显示内圈，不显示钱面；落定后钱面保留在本爻行，便于逐爻核对。
- 摇动时钱币在托盘内左右错位抖动、钱面每 60ms 交替；钱币描边变为 `UI_ACCENT`，并保留两枚 1px 强调色运动短线。
- 摇动结束恢复普通描边，三枚钱币归位；不使用图片、位图或常驻循环动画。
- 六爻堆栈每行 16px，保留三枚钱面、28×3px 爻线、6/7/8/9 与 `X →`/`O →`；当前爻行使用 `UI_SURFACE_ALT` 底色和 2px `UI_ACCENT` 左边线。
- 页面不显示问事类别，不显示自动吉凶。

### 8.2 颜色

- 背景、表面、边界、正文、次正文、强调、警示：使用 `UI_*` 语义角色。
- 五行：使用 `ui_theme_element_color()`。
- 当前选择：`UI_SURFACE_ALT` 背景加 `UI_ACCENT` 边界。
- 变向：`UI_ACCENT` 的 `X →` 或 `O →`。
- 旬空：正文色加边框，不使用危险色，因为“空”不是系统错误。
- 世应：正文色；“世/应”需要保持可读，不能只靠颜色。

### 8.3 字体

建议新增一个固定六爻标签的小号子集，只包含：

- 六神：青龙、朱雀、勾陈、螣蛇、白虎、玄武。
- 六亲：父母、兄弟、子孙、妻财、官鬼。
- 宫位、世应、变、化、空、破、冲、合、伏、原神、忌神、仇神。
- 摇卦页：摇、铜、钱、枚、静、背、字、待、未、落。
- 十天干、十二地支。

字号建议：

- 六爻主盘：12px 固定标签，行高 16px。
- 卦名：20px，使用已覆盖的 `ui_font_20`；缺字时改用 `buddy_font_16`。
- 摇卦页钱面：20px `liuyao_title_20` 的“背/字”。
- 详参标题：20px。
- 正文与底部说明：16px。
- 爻值与取数过程：Montserrat 14 或现有 32px 数字字体。

新增 12px 字库必须使用现有生成脚本并经过 `check_fonts`、`check_title_glyphs` 检查，不能只凭浏览器字体效果判断。

## 10. 数据模型与资源预算

建议核心结构：

```c
typedef struct {
    uint8_t value;        // 6..9
    uint8_t branch;
    uint8_t stem;
    uint8_t relative;     // 父母/兄弟/子孙/妻财/官鬼
    uint8_t spirit;       // 青龙..玄武
    uint8_t changed_relative;
    uint8_t changed_stem;
    uint8_t changed_branch;
    bool moving;
} liuyao_line_t;

typedef struct {
    uint8_t method;          // 0=时间起卦，1=手动摇卦
    int16_t year;
    uint8_t month;
    uint8_t day;
    uint8_t hour;
    uint8_t minute;
    uint8_t line_values[6];  // 手动摇卦：初爻到上爻的 6/7/8/9
    uint8_t upper_trigram;
    uint8_t lower_trigram;
    uint8_t moving_line;     // 时间起卦的单一动爻；0 表示无动爻
    uint8_t moving_mask;     // 六爻动爻位掩码，bit0 为初爻
} liuyao_cast_t;

typedef struct {
    liuyao_cast_t cast;
    uint8_t original_id;     // 0..63
    uint8_t changed_id;      // 无动爻时与 original_id 相同
    uint8_t palace;
    uint8_t palace_element;
    uint8_t shi;
    uint8_t ying;
    uint8_t month_branch;
    uint8_t day_stem;
    uint8_t day_branch;
    uint8_t use_relative;
    liuyao_line_t lines[6];
} liuyao_chart_t;
```

预算判断：

- 64 卦表、纳甲表、六神表、六冲六合表：小于 6 KB。
- 单盘状态：小于 1 KB。
- 六爻 UI 对象：按现有八字页估计 15–22 KB LVGL 堆。
- 12px 固定标签子集：预计低于 20 KB Flash，最终以生成文件为准。
- 不创建 worker、TLS、音频缓冲或帧缓冲。
- 应用逻辑在进入页面时分配，返回启动器时释放。

这些是预算，不是真机测量结果。实现后需记录进入前、主盘显示后、返回启动器后的空闲堆和最大连续块。

## 14. 横屏候选

- 横屏效果图：[liuyao-landscape-preview.png](liuyao-landscape-preview.png)
- 可打开预览：[liuyao-landscape-preview.html](liuyao-landscape-preview.html)

### 14.1 结论

可以横屏。ST7789P3 面板与当前 `esp_lvgl_port` 已具备硬件坐标交换能力，现有显示初始化把 `swap_xy` 固定为 `false`（`components/bsp/src/bsp_display_lvgl.c:43-56`），LVGL 旋转后由端口调用 `esp_lcd_panel_swap_xy()` 调整 MADCTL（`managed_components/espressif__esp_lvgl_port/src/lvgl9/esp_lvgl_port_disp.c:776-808`）。

但 320×240 与 240×320 的总像素完全相同。横屏不会让文字自然变大，真正的收益是：

- 本卦和变卦左右各占一半，六行一一对齐。
- 上半部用日期、干支、旬空组成紧凑摘要表。
- 后续取用参断可以三列并置四神、生克和状态。
- 六爻行可以使用更宽的单行字段，减少省略。

代价是：

- 六行高度从竖屏约 26px 压缩到约 18px。
- 横握后实体键的空间方向改变，必须靠动作文案而不是箭头解释。
- 截图、唤醒清屏与所有写死 240×320 的调试工具需要单独核对。

### 14.2 推荐方案

起卦方式和手动摇卦保持 240×320 竖屏；确认成盘后只让盘面与双卦卦意进入 320×240 横屏：

```text
竖屏启动器
  -> 打开六爻
  -> 竖屏选择方式
  -> 时间法直接成盘或手动摇卦逐爻摇满六次
  -> 盘面切换为 320×240 横屏
  -> 卦意保持横屏
  -> 退出六爻
  -> 恢复 240×320 并返回竖屏启动器
```

不建议为了六爻把整机永久改成横屏。那会同时要求首页、启动器、八字、万年历、设置、媒体应用和开机动画全部重排，超出六爻首版范围。

### 14.3 横屏信息架构

主盘：

| 区域 | 尺寸建议 |
| --- | --- |
| 顶栏 | x=0，y=0，w=320，h=26 |
| 日期、干支、旬空摘要 | x=8，y=28，w=304，h=60 |
| 本卦与变卦盘面 | x=8，y=89，w=304，左右各 152，h=127 |
| 每卦标题 | y=90，h=24 |
| 六爻行 | y=115，每行 h=16 |
| 按键提示 | 分隔线 y=218，w=304 |

主盘左栏显示本卦的六神、六亲纳甲、爻线与世应；右栏显示对应变卦的六亲纳甲、爻线与变化来源。左右相同爻位保持同一水平轴，阴变阳标 `X →`，阳变阴标 `O →`。当前版本不提供单爻详参；确定进入双卦白话解释。

参断页：

- 第 1 列：用神、原神、忌神、仇神。
- 第 2 列：月建、日辰、变爻对本爻的生克方向。
- 第 3 列：空、破、冲、合、伏、动与化回头生等状态。

### 14.4 实现风险

横屏不是只改一行 `swap_xy`：

- 应用进入和退出时都必须持有 LVGL 锁并恢复方向，避免与页面交接并发。
- `main/ui/ui_capture.c` 已改为读取当前显示分辨率，截图同时支持 240×320 与 320×240。
- `bsp_display_fill()` 使用直接面板坐标，在横屏状态下清屏必须验证坐标映射。
- 息屏唤醒、应用切换和首次上电不能出现方向跳变或半屏刷新。
- 必须真机确认横握时三颗实体键的手感与“上下选择”是否仍然直观。
- 240×320 竖屏方案已经能完整容纳六爻，因此横屏应作为明确的“并置阅读”升级，而不是为了容纳更多内容而盲目缩小字号。

## 15. 参考样式提炼

用户提供的参考图采用以下视觉语言：

- 参考图主要作为视觉样式输入；手动摇卦规则按本文件 §7.1.2 明确定义，时间起卦规则按 §7.1.1 明确定义，手机端功能入口不照搬。
- 上部为青绿色章节面，页面主体为暖白案卷底。
- 字段名称使用赭金色，正文使用深墨色。
- 日期、干支、空亡用细线表格分组。
- 本卦与变卦左右并列，六行处在同一水平基准。
- 六亲、纳甲和五行关系有语义颜色，黑色爻线保持最高识别度。
- 主操作使用青色实底与白色文字。

这套语言适合六爻，因为它强化“核对一张盘”的工作感。设备版按以下方式改造：

| 参考图语言 | Passport OS 处理 |
| --- | --- |
| 青绿色大标题区 | 压缩为 24px 章节头，不占主盘高度 |
| 白色圆角卡片 | 使用方角表面与 1px 网格，不引入嵌套卡片 |
| 赭金字段名 | 只用于左侧字段标签，不用于数据本身 |
| 黑色爻线 | 保留连续与断开的线形，不依赖字符字体 |
| 语义彩色文字 | 复用五行主题色，并同时保留文字 |
| 手机大按钮和底栏 | 改为与实体键对应的“确定”“长按”动作条 |

浅色预览使用六爻局部“案卷场景色”，不能成为整机第七套主题。实现时必须把青绿、暖白和赭金映射到 `UI_ACCENT`、`UI_SURFACE`、`UI_TEXT`、`UI_WARNING` 等角色，并为深色主题保留可读映射。
