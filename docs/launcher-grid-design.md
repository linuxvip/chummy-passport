# 应用选择页：手机桌面式网格设计

实现状态：已完成并烧录验证。短按逐项移动和长按跨行均已在真机检查。

## 目标

把首页按“确定”后进入的应用页，从“一张大卡轮播一个应用”改成类似手机桌面的应用网格。用户一眼看到全部应用，移动焦点时逐项高亮，按确定打开当前应用。

页面只使用设备现有的上、下、确定三个实体按键，不增加触控或左右键依赖。

## 信息架构

- 顶部保留系统状态栏：Wi-Fi、电池、标题“应用”。
- 屏幕中央为最多 `3 × 4` 的应用网格，一屏展示全部应用。当前精简版共 8 个应用。
- 当前 8 个应用占 3 行：前两行各 3 个，第三行 2 个。
- 应用少于 10 个时按实际行数垂直居中：9 个应用占满 3 行，并适度增大行间距，
  不保留无意义的第四行空白。
- 底部两行显示按键说明。
- 不使用左右翻页，不出现滚动条。

## 网格排布

| 年 | 列 1 | 列 2 | 列 3 |
| --- | --- | --- | --- |
| 第 1 行 | 小智 AI | 城市收音机 | 网易云音乐 |
| 第 2 行 | 备忘提醒 | 文字清单 | 八字排盘 |
| 第 3 行 | 万年历 | 设置 | 空 |

每个应用格尺寸为 `70 × 54`：

- 图标区 `24 × 24`，沿用现有像素图标语言。
- 名称区使用紧凑的 12px 中文字体，单行居中。
- 横向间距 7px，纵向间距 6px。
- 聚焦格显示主题强调色描边、轻微底色和左上角焦点标记。

## 按键方式

| 操作 | 行为 |
| --- | --- |
| 上键短按 | 移到上一个应用，第一项继续向上则回到最后一项 |
| 下键短按 | 移到下一个应用，最后一项继续向下则回到第一项 |
| 上键长按 | 在当前列跨到上一行；越过第一行时回到该列最后可用项 |
| 下键长按 | 在当前列跨到下一行；越过最后一行时回到该列第一项 |
| 确定短按 | 打开当前高亮应用 |
| 确定长按 | 返回首页，由现有全局返回规则处理 |

短按采用“阅读顺序”逐项移动，确保每按一次都能确认焦点去到了哪里。长按用于跨行快速移动，减少在同一列中连续按多次的需求。

空位不参与选择。若跨行目标为空，会继续寻找下一有效行，并在目标行选择距离最近的可用应用。

如果只有 9 个应用，长按下键会从第三行直接回到第一行；长按上键会从第一行跳到第三行，
不会停在空白的第四行。

## 焦点与反馈

- 默认焦点：小智 AI。
- 焦点进入一个应用时，该格在 80ms 内上浮 1px 后复位，不改变网格位置。
- 焦点格使用 2px 强调色边框，并提高图标和文字亮度。
- 其他应用保持弱一档的正文色，避免十张卡片同时抢占注意力。
- 极简和浅色主题下通过边框、角标和明度共同表示焦点，不只依赖颜色。

## 键位提示

底部固定显示：

```text
上下逐项 · 长按跨行
确定打开 · 长按确定返回
```

## 实现边界

- 保留现有应用注册顺序、应用 ID 和打开逻辑。
- 每个应用格只创建一个容器、一个图标绘制区和一两个标签，避免为装饰保留大量对象。
- 页面只在应用选择页存在，进入重型应用时继续释放整套网格对象。
- 不改变首页的长按上、长按下手势，也不改变应用内部的按键逻辑。
- 不把设置放入隐藏系统页；设置仍作为普通应用保留。

## 验收要点

- 240×320 屏幕上当前 8 个应用全部可见，无横向或纵向滚动。
- 名称无截断、无重叠，5 字应用名称仍能完整显示。
- 短按上下能遍历全部 10 项并首尾循环。
- 长按上下能按列跨行，遇到空位时不会丢失焦点。
- 六个主题下焦点都清晰可见。
- 确定短按只打开一个应用，确定长按返回首页。
- 进入和退出应用选择页不产生界面对象或堆内存泄漏。
